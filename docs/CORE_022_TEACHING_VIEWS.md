# Complete human problems as executable teaching

I keep the earlier teaching views and results unchanged. The new view returns to
the original human question, worked solution or program, source hash and source
group. A worked arithmetic step is not renamed a complete solved problem.

For mathematics, every marked calculation must pass independent exact rational
arithmetic, and the final marked value must match the published final answer.
The learner sees the question and a deterministic inventory of numbers from the
question. It does not see the worked solution or intermediate answers. The
teaching target is a bounded executable graph assembled from the checked human
calculations. Numeric coincidences can admit several operand bindings; these
remain multiple candidate teaching graphs, with their ambiguity recorded. A
correct result on the original numbers certifies that instance, not the English
interpretation for arbitrary substituted numbers. Unrepresentable, ambiguous
overflow and incorrect-source records remain in the rejection/outcome ledger.

For code, I parse the human source without executing it. A declared scalar,
straight-line subset compiles into the same graph language. Independently parsed
human assertions must agree with a separately written graph interpreter. Calls,
imports, loops, containers and other unsupported syntax are recorded, not run.
The human function signature is supplied; the learner must propose the body.

Both use the existing finite graph space: at most four numeric inputs, eight
instructions and the nine declared scalar operations. Constants outside the
primitive alphabet require explicit arithmetic instructions. Graph targets are
separate from the input view. Probability is marginalized over compatible
teaching graphs and the existing imagined branches. All loss gradients reach
the actual common owner; no pretrained weights, retrieval of solution text, or
second program learner is introduced.

This source preparation opens training and development partitions only. Earlier
sealed partitions are hashed, not used to design this view. New course and final
allocation remain separately frozen before curriculum training. Human-source
authorship, supplied annotations and engineering transformations remain distinct
from what SERA subsequently learns.
